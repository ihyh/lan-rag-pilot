## O3 / P2 未关闭：25% 阈值遗漏了原来的同页混合反例

位置：`scripts/ocr_preprocess.py:711–739`，尤其 `:725`。

用上一轮 **同一份** `same-page-text-and-scan.pdf` 直接复跑：原生页眉有 71 个非空白字符，扫描正文包含上限 400 元与温度 18–27 摄氏度。PDFium 测得图像覆盖 **17.9679%**，低于新增的 25% 阈值，仍输出仅有页眉的 `text_layer`，页面 `ok`、无 warning、退出码 0，正文缺失。

本次提交的新同页验收样本扩大了图像覆盖，能够触发 OCR，页眉与正文均保留且 `suspect`；该正控制通过，但没有证明原 O3 已修复。报告明确了 25% 局限有帮助，仍不能关闭已经存在的原反例。

最小修复方向：保留原始失败输入为回归样本。对小于阈值但可能含正文的图像提供可见的“内容覆盖待核对”状态，或提供明确的强制混合页 OCR 入口；保留原生文字并能通过该入口恢复正文。不要仅扩大测试图像来满足阈值，也无需对所有带小 Logo 的文字页无条件 OCR。

## O5 / P2 新缺陷：混合页异常越过单页处理，或以成功退出

位置：`scripts/ocr_preprocess.py:614–622`、`:735–737`。

普通扫描页的 OCR 调用位于单页 try/except 内，而新增 `_mixed_page_record(...)` 调用没有相应保护；helper 只捕获渲染异常，没有捕获 `_ocr_page_record` 的识别异常。

独立两页 PDF / 假引擎控制，第一页满足混合页覆盖阈值，第二页为正常文字页：

1. 第一页 OCR 抛出异常时，异常上升为整个输入的 `document_failed`。没有 `.ocr.json` / `.ocr.txt` 输出，已可读取的原生文字和第二页均未保存。应记录第一页失败与原生文字，继续第二页，并输出保留页码的部分结果。
2. 第一页渲染抛出异常时，原生文字和第二页得以保留，但第一页被标为 `suspect`，`failed_pages=0`，运行**退出 0**，同时 JSON 又含 `mixed_page_render_failed` 错误。这与普通扫描页 `render_failed` 的失败口径不一致，也违反工具“有失败页退出 1”的约定。

最小修复方向：混合页复用同样的单页失败边界；渲染/识别异常均记录明确的失败状态、错误码和保留下来的原生文字，继续后续页，最终非零退出。无需新增整套容错框架。补测“首个混合页失败、后续文字/扫描页正常”和“前面已有成功页、后面混合页失败”。

## 需要 DeepSeek 修复

### R4 / P1：长驻 MCP 的索引永久停留在首次调用时

位置：[scripts/mcp_server.py](../../scripts/mcp_server.py)，`KnowledgeBase.ensure_ready` 第 78–94 行，尤其第 79–83 行；全库范围解析第 140–150 行。

首次调用之后 `_ready` 永远为真，后续直接返回，内存向量/词法索引没有任何刷新路径。新连接查询 SQLite 的列表/原文已经更新，但检索仍用旧快照。真实 SDK 的同一个 stdio 会话实测：

1. 初次限定文档 1，检索正常。
2. 另一个连接提交新的 ready 文档 3 及有效 mock 向量。
3. `list_documents` 能看到 3，`get_document_text(3)` 能读取完整文字。
4. `search_documents(..., document_ids=[3])` 却返回空、`empty_reason=no_hits`。
5. 将旧文档 2 状态改为 failed，列表已排除 2，全库检索却仍返回 2 的片段。全库 `_resolve_scope` 返回 None，没有用最新 ready 集合限制旧索引。
6. 只重启 MCP 子进程，不改资料，再搜即得到文档 1、3，且不再返回 2。

影响：日常导入/重新处理后，客户端无法查询新资料，也可能继续使用非就绪资料；`ask_question` 同样复用这条路径。不能认为首次启动时与网页来源一致，就证明长驻进程持续一致。

最小修复：建立可检测资料/切片变更的刷新机制，在检索前同步索引，并按当前 ready 集合过滤；不要无条件每问重新加载嵌入模型，也不要只刷新文档列表。可复用现有索引 reload，但要覆盖新增、删除、状态变化及同文档重建。

复测：**同一 MCP 会话不重启**，添加/删除/改状态/重新索引，分别核对列表、检索、问答来源；与网页在相同库版本和参数下对照。保留无命中及范围过滤控制。

### R5 / P2：接受多页 TIFF，却静默只取第一页

位置：[scripts/ocr_preprocess.py](../../scripts/ocr_preprocess.py)，图片分支第 563–566 行，以及 `ImageFileRenderer.render` 第 278–280 行。

支持扩展名包含 `.tif/.tiff`，但所有图片均硬编码 `source.pages=1`，renderer 也没有按帧 seek。使用真实 Pillow 保存两帧 TIFF、真实图片解码和假识别器复现：输入 `n_frames=2`，输出只有第一页，文件/页面均 `status=ok`、warnings 为空，第二页证据完全丢失。

最小修复：逐帧处理并保留页码、页选择/数量上限；如暂不实现多帧，至少检测 `n_frames>1` 并明确拒绝，不能报完整成功。单帧图片保持原行为。

复测：两帧 TIFF 分别放不同编号/正文，验证两页映射与文字均保留（或得到明确不支持错误），另测第二帧失败及 `--pages 2`。

### R6 / P2：低置信度的关键行被页面均分掩盖

位置：[scripts/ocr_preprocess.py](../../scripts/ocr_preprocess.py)，第 406–417 行。

`uncertain_lines` 会记录低分行，但不增加 warning；仅页面平均分低于阈值才变成 suspect。默认阈值下，9 行分数 0.99，加一行含压力数字的 0.55，均分 0.946，仍输出 `status=ok`、warnings=[]、文件 ok；低分关键行只藏在 `uncertain_lines`。独立持久化用例使用 0.10 也复现同样情况。后续消费者若按 summary/suspect_pages 决定是否复核，将跳过这页。

最小修复：只要存在低于 line_score 的行，就给页面增加明确 warning 并置 suspect，保留现有逐行原文/分数；不要删除可疑行或推测数字。可疑页是否非零退出保持既有约定，无须当成处理失败。

复测：高均分 + 一条低分数字/单位行，应为 suspect/partial；全部高分页维持 ok；没有分数时仍不得伪造。

### R7 / P2：未开启覆盖也会覆盖旧运行清单

位置：[scripts/ocr_preprocess.py](../../scripts/ocr_preprocess.py)，第 734–735 行。

同一 PDF、同一输出目录连续执行两次，均不加 `--overwrite`：首次成功；第二次正文/JSON 被 `output_exists` 拒绝，退出码 1，但最终仍无条件写 `ocr_run.json`，把第一次成功清单替换成失败清单。以处理新增文件的方式再次使用目录，也会丢掉先前批次的汇总来源映射。这与“已有同名输出默认拒绝”的约定不一致，妨碍保留失败/成功证据。

最小修复：统一清单和各输出的覆盖语义；可在处理前拒绝已有清单，或每次生成唯一清单名。未经明确覆盖时，不更改原清单。

复测：首次运行后记录所有输出 hash，再原参数重跑；若拒绝，原输出和原清单必须完全不变。另测同目录新一批输入和明确 `--overwrite`。

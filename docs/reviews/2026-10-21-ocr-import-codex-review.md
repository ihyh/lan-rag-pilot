## I1 / P1：报告路径可以覆盖原始 PDF 或旧证据

位置：`scripts/import_ocr_to_rag.py:261–262`，参数预检 `:64–68`。

只有 DB/上传目录受到隔离路径校验，`--report` 无存在性或路径别名保护，最终直接 `write_text`。

独立反例在新建、审核者拥有的合成目录中，让 `--report` 与 `--source` 指向同一 PDF。命令退出 0，`source_ok/mapping_ok/expectations_ok` 均 true，但**输入 PDF 被报告 JSON 覆盖**。`source_ok` 检查的是上传副本，未再次检查用户原件，掩盖了破坏。相同写法也会无条件覆盖先前报告，或破坏作为 report 目标的其他文件。

最小修复：任何入库写入前，解析并拒绝报告与 source、ocr-json、db 等路径相同；报告默认必须是不存在的新文件，用排他创建保存首轮证据。保留隔离路径约束。此处需要的是防误覆盖，不是新权限系统。

复现仅覆盖合成副本；没有改写用户业务资料。被覆盖测试原件的原始字节仍保存在该用例的上传副本中，失败现场保留。

## I2 / P2：缺少来源哈希仍导入并宣称校验通过

位置：`scripts/import_ocr_to_rag.py:35–44`、`:217`。

`if meta.get('sha256') and ...` 只拒绝“存在且不相等”，没有拒绝缺失/空哈希。移除 OCR JSON 的 source.sha256 后，导入仍成功，报告却无条件写 `sha256_matches_ocr=true`。因此来自另一文档的文本也可以被绑定到任意传入 PDF，工具不能证明来源一致。

最小修复：要求非空、格式有效的 SHA-256 并与原件核对；缺失不能报告为 true，当前声明的已核对输出入口宜直接拒绝。补测缺失、空值、错误值和正确值，在建立 DB/复制来源前完成校验。

## I3 / P2：未验证物理页码和重复页，失败页可能被重新索引

位置：`scripts/import_ocr_to_rag.py:88–106`；对应测试 `tests/ocr_import_check.py:33–50`。

两类独立反例均退出 0 并宣称 mapping_ok：

- 原件只有两页，OCR JSON 的第二条记录改为 `page=7`，工具写入并召回“第 7 页”，`expect_page=7` 也通过；它只证明 DB 与返回值一致，没有证明该页存在于原 PDF。
- 两条 `page=1`，第一条状态 failed、含失败文本，第二条状态 ok。statuses 字典被后一条覆盖，两条都按 ok 导入；失败文本实际进入 chunk，`skipped_failed=[]`。相同页码的内容又被合并，失败页过滤被绕过。

提交测试使用的是**零页 PDF**，却声明三页 OCR，因此其 13 项通过不能证明物理页码成立。

最小修复：对本轮 PDF 入口读取真实页数；要求页码为正整数、唯一、在真实范围内，拒绝重复/冲突状态。明确只允许约定可导入状态，failed/skipped 不得被其他记录改写。将正向测试改为实际存在相应页数的有效 PDF。若以后支持图片/TIFF，另按其实际帧数验证，不在本轮推断支持。

## I4 / P2：复用隔离库时，旧文档可以替新文档通过验收

位置：`scripts/import_ocr_to_rag.py:177–178`、`:184–196`。

导入后 `retrieve_sources(..., None, ...)` 查询全库；校验只比较返回来源与其自己的 DB 行，没有约束为刚导入的 doc_id。failed_page 判断还用新文档的页状态解释其他文档的同号页。

独立复现：先往同一隔离 DB 导入“限额 400 USD”的旧文档，再导入只含“限额 50 USD”的新文档。验证新文档中的 400 USD 时，来源包含旧文档，工具依然退出 0、expectations_ok=true。不是要求支持生产多租户，而是同一测试库内的来源归属错误。

最小修复：此单文件导入验证用 `{doc_id}` 限定检索；将 document_id 纳入返回与 DB 核对，页状态也按该文档身份判断。若想评估全库场景，应作为另一个显式实验，不用其结果证明本次导入成功。

## I5 / P2：页码命中和关键字命中来自不同页也会通过

位置：`scripts/import_ocr_to_rag.py:198–201`、`:255–256`。

`page_hit` 与 `token_hit` 在整个来源列表上分别 any，最终相与，未要求同一片段满足两项。

独立两页样本：第 1 页只有普通标题，第 2 页才有 `400 USD`。指定 `expect-page=1` 和 `expect-token='400 USD'`，返回两页后 `page_hit=true/token_hit=true`，命令退出 0，尽管第 1 页从未包含该事实。用户最需要核对的“这个事实来自哪一页”没有得到验证。

最小修复：同一来源必须同时满足目标 document_id、页码和关键字；若一个问题要验证多份必要证据，应明确列举要求，不用独立 any 拼接成功。补测关键字在正确页、相邻页、其他文档、完全缺失四种情况。

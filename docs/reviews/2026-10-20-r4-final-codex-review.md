## 修复机制与独立验证

首次加载和后续刷新都使用 `_reload_index_consistent`。真实索引加载与 loaded 指纹在同一个显式 SQLite 读事务内读取，避免把未加载的新提交版本记录为已加载。事务结束后检查最新指纹，最多重试三轮；仍有写入时保留与当前索引对应的 loaded 指纹，下一次调用继续检测。

独立验证结果：

| 检查 | 结果 |
| --- | --- |
| 原首次加载竞态 | 通过：在 reload 后、指纹读取前提交的新文档可被随后查询召回 |
| 原后续刷新竞态 | 通过：连续三次限定检索有结果，问答返回 ok，不再永久 no_evidence |
| 两个重新初始化正控制 | 通过；现在无需靠重启才能恢复 |
| 连续三轮都有提交 | 通过：重试有上限，保存 loaded 而非尚未加载的最新指纹 |
| 停止写入后的下一次 search / ask | 通过：不重启即可补齐最后一次提交，指纹恢复一致 |
| 资料不变时反复查询 | 通过：不重复调用 reload |

竞态复测仍使用真实 SQLite/WAL、真实索引和检索函数，仅在指定边界通过另一个连接提交合成文档；没有用伪造搜索结果替代执行。生成调用与 RAG 嵌入为 mock，不访问真实模型。只将旧复现脚本的末尾断言从“确认缺陷存在”改为“所有场景必须通过”，原期望与观察逻辑不变，旧失败证据不覆盖。

# 离线原文字面保真诊断

> 历史开发专题：下文的日期、验证数量、候选状态和本机报告仅描述当时阶段，不是当前安装步骤。MCP 已移除；未随仓库提供的脚本不可直接运行。现有功能与默认边界以 [开发进度](../ROADMAP.md) 为准。

用于核对**已保存答案**中的数字、网址和部分技术标识符是否原样出现在给定来源正文。它不调用模型、数据库或网络，不修改答案，也不参与在线回答、阻断或自动修复。

## 使用

准备 UTF-8 JSONL，每行是一条答案及当次完整来源，数组顺序对应引用 `[1]`、`[2]`：

```json
{"id":"example","answer":"速率为1152。[1]","sources":[{"content":"默认速率为115200。"}]}
```

```powershell
python scripts/answer_literal_audit.py --input saved-answers.jsonl --output new-audit.jsonl
```

必须显式指定文件；输出目录需已存在，已有报告和输入文件不会覆盖。不要用界面截短的来源摘要代替当次完整正文。报告不含完整答案/来源，但会保留抽取的原文值，仍可能包含私有信息，请留在本地。

成功执行返回 0，即使有待复核项；输入行错误会写成 `input_error`，继续处理其他行，最后返回 2。退出码不是答案验收结果。

## 报告含义

- 原始答案及各来源正文 SHA-256、输入文件 SHA-256 和行号，便于核对输入身份。
- 每个候选字面值的答案位置、全部同字面来源位置，以及三类出处：出现在被引用来源、只出现在其他来源、未在来源正文发现。
- 偏移为 **Unicode codepoint、从 0 起、右端不含**；不是 UTF-8 字节或 JavaScript UTF-16 索引。
- `literal_match` 仅表示同类完整 token 原样出现；大小写、精度、符号和后缀不归一化，不做单位换算。`1ms`、`1s`、`1e` 等保留后缀，不丢掉差异再匹配。
- `literal_review_required` 是字面/语法疑点，不是错答判决。单位换算、四舍五入等合理答案也可能触发。
- 引用只在整答范围汇总，不证明某条事实引用正确；`only_uncited_source_content` 也不表示补一个引用即可通过。

## 必须保留的边界

`manual_review_required` 始终为 true；`human_verified` 为 false；`fact_supported` 和 `whole_answer_supported` 始终未知。即使全部字面匹配，也不能证明对象、字段关系、否定、条件、适用范围或冲突处理正确。例如把 START/STOP 的两个值交换，或只选冲突中的一个值，本工具仍可能找得到所有字面值。

这是启发式候选抽取，不是完整的 Markdown、数字、单位或报文解析器：

- 只查 `sources[].content`，不查文件名等元数据；普通自然语言无依据扩写不在检查能力内。
- 数字方括号和行首 `1.` / `2、` 等按引用/列表前缀启发式处理，并保留忽略位置；状态码可能与排版编号相同，不能宣称数字全部检查过。数据方括号应使用反引号，已识别的 `U2[3]` 等协议类型不会作为引用。
- URL 内部或紧贴末尾的 `[数字]` 可能是网址正文，也可能是引用，原串保留在 URL 中，标为 `ambiguous_url_brackets`，不擅自计为有效/无效引用。请用空白分隔网址和引用。仅对明确的 Markdown 链接目标闭界、引号做格式边界识别，不修补或标准化 URL；其他标点可能触发复核。
- 中文单位、分离的单位、复杂公式/排版及未识别标识符仍需人工检查。`coverage_complete=false`，不能以没有疑点代替人工整答验收。

新合成边界检查在 `tests/answer_literal_audit_check.py`。已消费的失败答案只能用于回溯诊断，不作为新留出测试或业务正确率。

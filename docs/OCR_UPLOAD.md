扫描或混合 PDF 可在“资料管理”勾选“先 OCR，再由我核对入库”。PNG/JPEG 图片自动进入OCR核对流程；这部分于2026-10-24完成开发与隔离验收，已随10月26日19:13基础版本部署。普通上传保持原样，不会自动重处理已有资料。

## 使用

1. 勾选 OCR 后上传 PDF，查看排队/识别状态；每份限制 20MB、50 物理页，子进程最多运行180秒。
2. 点击“查看 / 核对OCR”，展开各页，对照“打开原PDF”检查正文、数字、单位、表格行序。置信度不是正确率保证。
3. `ok` 页进入待确认集合；`suspect` 页必须逐项勾选；`failed` 页（包括未识别出文字的页）不能入库。
4. 有排除页时须明确确认资料不完整，再点“确认所选页并入库”。这之前新文档没有可检索的 chunks。
5. 可“重试失败页”。存在上一份完整结果时仅处理失败物理页，保留其他页和旧结果，再次核对后发布。已发布的旧索引在新结果确认前不被替换。

PNG/JPEG：原图限10MB、2000万像素、单帧。核对弹层同时显示原图和OCR文字；即使引擎为`ok`也必须手动勾选确认。空白/失败内容不能入库，未确认图片不会出现在问答文档范围中。所有图片只纳入核对过的文字，图中箭头、表格关系和阅读顺序仍未验证；引用显示“原图 · OCR文字”，不会伪造PDF页码。当前不提供OCR文字编辑，不合格结果可先保留或重试。

图片核对窗口绑定本次识别结果；重试产生新结果后，旧窗口提交会被拒绝，需重新打开核对。API仍沿用`accepted_suspect_pages`选择单图frame1（包括ok图片），并要求inspect返回的`review_token`；此内部frame号不作为检索页码。PDF调用兼容原契约。图片确认响应使用`indexed_images`，PDF使用`indexed_pages`。

同内容上传遵循原有 SHA 去重：失败任务请点重试，不重复上传。不能用普通“重建索引”绕过 OCR 页状态。

## 独立环境（Windows，项目根目录）

```powershell
py -3.12 -m venv .venv-ocr
.\.venv-ocr\Scripts\python.exe -m pip install -r requirements-ocr.txt
.\.venv-ocr\Scripts\python.exe -I scripts\ocr_upload_worker.py --probe
```

环境仅用于本机 OCR 子进程，不替换问答主环境。默认自动识别项目根目录 `.venv-ocr`；另行部署可用 `RAG_OCR_PYTHON` 指向独立解释器。脚本 `ocr_upload_worker.py` 与 `ocr_preprocess.py` 须同时保留。缺少依赖时管理页禁用 OCR 勾选，但普通上传/问答不受影响。

## 数据与边界

- `ocr_jobs` 持久化任务状态；PDF原件按现有 UUID/SHA 保存并保留物理页，PNG/JPEG同样保存原字节，索引`page=NULL`、`paragraph=1`，文档页数为空。文字框/旋转元数据保留在OCR结果和核对API中，尚未提供框高亮定位。
- 每次原始结果、合并结果、子进程日志使用独立文件，保存在 `data/ocr-results/<document_id>/`；不得提交私有正文到 Git。
- 发布在事务内更新该文档 chunks、tags、任务状态与审计；失败回滚。旧问答和保存的引用摘录不重写。
- 每次仅运行一个 OCR 子进程；不是通用可恢复任务队列。服务重启时识别中/排队任务标为失败，需手动重试；待核对结果继续保留。
- 本版本不支持在线改写识别正文、批量确认、GIF/WebP/TIFF图片上传。可疑页宁可不发布；复杂排版仍需人工核对。网页56图的隔离结果没有被自动转成生产资料，文章归属的正式导入仍待做。
- 原始结果文件暂不自动清理；硬删除文档会删除任务记录，但私有结果证据保留在磁盘。备份时应一并保留 `data/ocr-results`、数据库和原始上传文件。

验收分别记录流程执行、正文/页码映射、整答支持程度；不能把模拟嵌入或合成扫描样本成绩当成真实业务回答正确率。

图片本轮验证含真实本地OCR的PNG/JPEG数值恢复、空白/多帧/损坏图阻断、手动确认前无索引、原件SHA、单图位置和检索/历史来源。实际隔离浏览器验证原图显示、无默认勾选、未确认提交被阻止、确认后ready且重开只读；1440×900、1920×1080、390×844、360×800没有页面横向溢出。这不是实际iPhone、文件选择器上传或真实业务答案验收。

# 反馈审核、正确来源与隔离复测题

入口：root 登录“资料管理 → 审计 → 用户反馈 → 核对 / 处理”。文档管理员和普通用户仍不能查看全局反馈。

“有帮助”的反馈保留在列表中，显示“无需审核”，不计入待审核；如评价改为“没帮助”，则按当前反馈内容进入审核流程。已有审核历史不删除。

## 最小人工闭环

1. 查看完整问题、原回答、用户补充、原引用摘录、原文档范围及最近上下文。原回答和旧审核不能在此改写。
2. 选择处理状态；分类可选。确认问题时填写核对结果或期望回答，来源及适用范围可按需补充。
3. 如需保存复测核对信息，展开“补充证据和复测”，明确资料是否足够，填写完整独立问题并核对正确来源和范围；不默认“能回答”。
4. 保存为“已确认问题”后，审核结果保留在系统中；未确认资料是否足够时该字段保留为空，不推定为可回答。
5. “已解决（人工确认）”还须填写修复/复测记录。这是人的判断，不是自动通过标记；仍须逐项对照原文核对整段回答，不用关键字命中替代事实支持。

状态还有“待审核”和“不采纳”（必填原因）。可以保留空草稿。列表可删除单条反馈及其审核记录，原问答、引用与资料不受影响。

## 保留与并发

- 每次保存追加一条 `feedback_reviews`，原反馈、问答、来源摘录、文档、向量不变。弹窗显示最近10次审核摘要，完整修订保留在DB。
- 若用户另行显式删除原问答/反馈，关联审核记录按外键级联删除；这里的“不覆盖”不等于不可删除的永久存档。
- 用户修改评价/补充或原问题/答案内容发生变化，旧审核自动失效，显示待审核；旧审核快照仍保留。内容完全相同的重复提交不会误触发重审。
- 请求携带反馈内容hash和上一条审核ID。过期弹窗返回409，不覆盖新记录；保留输入以供复制、关闭并重开核对。
- 审核追加和审计写入同一事务，失败整体回滚。审核只是人工工作记录，不会训练模型、改提示词、重建索引或自动发布答案。

## 结构化正确来源

在“核对 / 处理”窗口展开“补充证据和复测”，点击选择正确来源，输入正确原文关键词，人工选择片段并按需缩小为连续逐字摘录。原模型引用不会自动勾选。每片段最多一条摘录，跨片段分别选择；最多20条。页码是PDF页，段落标记仅表示片段起始段落。

保存时核对片段所属文档、文档SHA/版本/状态/适用范围和索引正文SHA，摘录必须逐字存在。服务器重新取得文件名和位置，不接受客户端编造出处。选择后资料变化会返回409，旧记录和当前表单保留。该检查只证明索引映射一致，不证明OCR还原正确或答案受原文支持；仍须人工对照原件。

缺少有效页码和起始段落的普通来源只能保存诊断，不能确认复测资料。直接入库的图片人工说明可按原图 SHA 和说明片段 ID 定位，无须伪造页码；保存和复测仍会检查原件、说明和权限。可先在“资料检查”核对定位问题。

## 审核中的复测资料

每次打开审核窗，复测资料默认不重新确认。要确认须人工核对完整独立问题、期望答案、能否回答和正确来源；不能回答的题明确写应如何说明资料不足，且不把片段列为答案支持。

- 追问必须人工补成独立问题，原问题/回答/最多6轮参考上下文保留，但不会注入重放或冒充模型原本使用的历史。
- 原限定文档范围不扩大；原全库固定为审核时原账号可见、就绪、启用的文档（最多100份），并明确标记是审核时范围，不冒充历史全库。
- 冻结文档ID、文件名、SHA、版本以及包含所有片段/位置/适用范围的索引摘要。原账号停用/撤权、来源或范围内任一资料改变，均使复测记录不再就绪，直到人工重新核对。
- 历史或原范围外的正确来源可以记录诊断，但不能伪装成同范围复测。

此处保存的是审核信息；当前管理页面不提供反馈导出。不自动执行、不训练模型、不改生产提示词或索引。

# 离线与安全上线要求

[返回首页](../README.md) · [代码边界核对](SECURITY_AUDIT.md)

本项目不能承诺“绝对安全”。严格离线是可验证的网络约束：运行设备不能到达互联网，但可以进行经批准的本机与局域网通信。断网不能消除恶意文档、越权、弱口令、介质泄露、终端截屏或管理员滥用。

## 第一项上线门槛：文档授权

**已实现按账号的文档级授权，未实现按部门/组隔离。** 文档默认「所有人可见」，`root` 可把
单份文档改为「仅指定账号可见」；受限文档在检索、文档列表、原文访问、历史对话四条链路上
对未授权账号均不可见，撤销授权后旧对话中引用过它的那一轮同步隐藏。
`root` 与 `kb_admin` 不受此限制（否则无法管理受限文档），管理员打开受限原文会写入审计。

仍需注意：默认是共享库；**设备范围、文档筛选和历史上的部门字段都不是安全边界**；
没有组/部门概念，因此无法"一次授权给一个组织单位"。需要按部门隔离的企业环境，
应在此基础上补齐组管理后再上线。

未来至少需要：

- 服务端在文档列表、上传归属、检索候选、引用/下载、历史回答、导出、重处理与删除统一校验授权。
- 撤权后处理旧会话、缓存与已存回答；root/文档管理员的例外权限经审批并审计。
- 两个不同授权域的合成资料与用户，验证直接猜测 ID、跨会话、篡改范围也不能越权；不能只测试页面看不到按钮。

这些是待实现及验收要求，**不是本次文档更新已提供的功能**。当前仅适合个人或所有账号均获准读取同一资料集的受控试点。

## 网络边界

| 通信 | 规则 |
|---|---|
| 普通客户端 → 服务器 | 仅批准网段至内网 HTTPS 443 |
| 反向代理 → RAG | 同机回环 8088 |
| RAG → Ollama | 同机回环或隔离容器网络；模型端口不向客户端开放 |
| 运维 → 服务器 | 独立管理网及批准端口；普通用户无 SSH/Docker 权限 |
| 运行设备 → 公网 | IPv4/IPv6、DNS、代理、容器转发等全部拒绝，默认拒绝出口 |
| 软件准备与介质导入 | 独立准备机，核验签名/摘要，介质扫描与审批 |

IT 需确认无第二块网卡、Wi-Fi、VPN、代理或网关绕过。对服务器、模型主机、客户端、备份存储共同定义边界；浏览器同步、在线输入法、云剪贴板、扩展、远程协助也可能泄露资料。

HF_HUB_OFFLINE=1、TRANSFORMERS_OFFLINE=1 和 OLLAMA_NO_CLOUD=1 是应用设置，不是防火墙。缺失的 DEEPSEEK_BASE_URL 会回退到公共 URL，必须显式配置本机/内网地址。RAG_PUBLIC_ORIGIN 不是外联限制或来源白名单。

Docker 的端口发布与防火墙要检查实际生效结果，不能只看 UFW。官方提醒发布端口与主机过滤规则有交互：[Docker 端口发布](https://docs.docker.com/engine/network/port-publishing/)。

## 身份与传输

使用个人账号、唯一强口令、最少管理员；离职/调岗及时停用并复核历史可见性。当前没有 MFA/SSO，不宣称企业身份体系已接入。

必须设置随机 RAG_SECRET_KEY。代码在缺失时会**直接拒绝启动**（错误信息给出生成命令），不再回退固定开发密钥。同一轮校验还会拒绝指向公网的模型地址，以及 HTTPS 来源配 `RAG_COOKIE_SECURE=false` 之类的矛盾配置；`RAG_ALLOW_INSECURE_START=1` 可显式跳过全部校验，只允许用于本机调试。RAG_ROOT_PASSWORD 只初始化空库，修改环境不能重置已有账号。

LAN 用 HTTPS 与受信任内部 CA，RAG_COOKIE_SECURE=true；限制会话时长。HTTP 回环例外仅用于个人同机部署。不要把长期登录误认为不会被盗用。TLS 是传输保护，不是文档访问授权。[OWASP TLS 指南](https://cheatsheetseries.owasp.org/cheatsheets/Transport_Layer_Security_Cheat_Sheet.html)

当前使用 Argon2id 密码哈希、随机会话令牌及 HttpOnly/SameSite Cookie。写请求有条件式 Origin/Referer 校验，不能据此宣称已完成全面 CSRF 防护。

## 文档、主机与存储

- 上传来自获准来源；检查扩展名/MIME/魔数/大小只是第一层，不能证明文件无恶意内容。使用受控离线扫描/解析流程，尤其关注压缩型 Office 文件和解析库漏洞。
- 不把宏、嵌入对象或文档中的“操作指令”视为可信命令；模型也可能受文档提示注入影响。用户必须核对回答原文。
- 当前没有完整杀毒、解析沙箱、压缩展开配额或自动敏感数据识别承诺。[OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
- 应用默认并不加密 SQLite 或上传文件。用组织管理的磁盘/卷加密、访问权限和物理保护；密钥与备份分开保管，加密不能限制正在运行的高权限管理员。
- Dockerfile 默认以 root 运行，不是已经完成最小权限容器加固。正式环境应另行实现并验证非 root、资源限制等措施，不能只修改文档便宣称完成。
- 不挂载 Docker socket，不给应用不必要主机目录、特权或管理凭据；保持单 worker/单副本。
- 安全补丁也需经准备机制作新包、离线验收与维护窗口更新；永久不更新并不更安全。

## 备份与审计

按 [运维指南](OPERATIONS.md)加密备份、异机/离线留存并恢复演练。原文、问答、日志和评测报告都属于业务数据。删除文档不保证旧问答、备份或终端副本同时消失，保留/销毁策略需覆盖全部副本。

审计记录在同一应用/数据库体系内，不是不可篡改审计平台。需要高保证时，应另外设计受控的防篡改归档和独立审计权限。

## 离线验收怎么做

由 IT 在维护窗口使用不含业务信息的测试流量：

1. 确认网络/主机策略默认拒绝所有公网出口，包括直接 IP、外部 DNS、IPv6、代理和容器网络；只有批准内网目的地放行。
2. 从主机与每个运行容器按批准测试计划发起无敏感探测，连接必须失败，并在边界日志看到拒绝。只测一个域名失败不等于全面阻断。
3. 无公网条件下重启，首次加载模型并完成文档上传、检索、流式生成、引用、备份恢复。
4. 从允许与禁止的客户端网段验证入口边界，模型端口和数据库不可直接访问。
5. 记录政策、规则导出、监听状态、探测结果、模型摘要和验收人。不要为了验证先给业务主机开放外网。

## 上线签字清单

- [ ] 所有使用者可读同一资料集；若需要隔离，授权功能与越权测试先通过（当前阻塞）。
- [ ] 网络出口拒绝、入口白名单、容器及 IPv6 路径验收通过。
- [ ] 强口令/随机密钥/账号治理、内部 HTTPS/CA/Secure Cookie 已落实。
- [ ] 主机、文档解析、依赖供应链风险经审批，软件许可已检查。
- [ ] 数据加密、备份恢复、日志/保留制度及应急负责人明确。
- [ ] 真实问题质量、错误拒答、引用与负载验收有记录。
- [ ] 本机的实际部署版本已记录，不能引用历史服务器测试替代。

任何强制项不通过都应停止正式部署。发现漏洞通过 [内部报告流程](../SECURITY.md)处理，不在公开 Issue 放原文、密钥或数据库。

# DeepSeek 开发 / Codex 审核交接

更新：2026-10-20。本文是后续开发要求，**不表示这些新功能已经实现或部署**。

## 分工和主线

- DeepSeek 负责方案、实现、测试和根据评审意见修正；Codex 负责阅读实际差异、复现关键问题、审查测试和返回修改清单。未经另外要求，Codex 不同时重写同一功能。
- 每轮只提交一个可验收的小任务：开发 → 提交差异及测试 → Codex 审核 → 修正 → 复审。用户已确认通过 **Git 分支、提交或 PR** 交付代码。没有自动联通或自动向 DeepSeek 发消息；由用户提供审核目标。
- 当前产品是 **Windows 个人知识库**，优先回答准确、引用可信、能实际使用；不恢复 Linux 企业版、CEID 特例或固定答案。不新增企业权限平台、复杂审计或与当前需求无关的安全工程。
- 保留现有登录、私有文件保护、基本输入校验和防误删措施。文档范围与来源追踪也是准确率要求，不因个人使用而取消；不自动把私有资料传给外部模型服务。

## 第一轮：手动勾选文档（先完成这一项再审查）

现状不是完全没有此功能：

- [app.html](../app/templates/app.html) 已有折叠的“限定文档”区域；[app.js](../app/static/js/app.js) 的 `renderDocumentOptions` 已渲染复选框。
- 同文件 `loadDocuments` 失败提示为“将使用全部文档”；未勾选也表示全部文档。这是可能扩大检索范围的源码行为，尚未证明是用户当前手机界面的具体根因。
- [query.py](../app/routers/query.py) 已接收 `document_ids`，首问绑定会话范围，后续改范围要求新建会话；优先复用。先核对实际部署文件与浏览器缓存，不重复建设已有控件。

开发范围：把选择入口做明显，支持按文件名搜索、单选/多选、显示已选文件和数量；明确区分“全库检索”和“仅选中文档”。清空勾选不应偷偷切到全库。设备快捷按钮可保留，但替换手选范围必须清楚可见。手机端可正常点选，不引入新前端框架。

验收：

1. 新会话可选择一个或多个已就绪文档，首问请求携带正确 ID，检索和最终引用均不越出所选范围；使用含相似内容的范围外文档验证。
2. “仅选中文档”却零勾选、列表加载失败、所选文档已删除或不可用时明确提示/重试，不回退全库。显式全库模式仍正常工作；如新增范围模式字段，后端同步校验其语义。
3. 搜索、全选、清空的作用范围写清，筛选列表不能丢失原来勾选；刷新/历史恢复显示真实会话范围。会话开始后换范围引导新建会话。
4. 桌面与手机实际操作通过，普通问答、流式回答、引用展开及历史记录回归通过；不能仅凭 DOM 中存在复选框判定完成。

## 第二轮：OCR 预处理小工具

[parsing.py](../app/parsing.py) 的 `parse_pdf` 目前只抽取文字层：全无文字则报 `scanned_pdf`；部分页有文字时，无文字页不产生 `Unit`。据此推断混合 PDF 有漏页风险，尚未对用户全部文档逐页审计。

先交付独立、本地运行的预处理工具，再考虑接到导入界面；不要直接全量重建现有索引。OCR 依赖与默认安装隔离，先给出 Windows/CPU 可运行方案、依赖和模型体积，再按必要性选择一个引擎，不同时接多套。

验收：

- 支持扫描 PDF/图片，以及文字页与扫描页混合的 PDF；按页判断是否需要 OCR，保留可用文字层，不能只检查整份文件的总字数。
- 原件不覆盖；输出文本及页码映射、来源摘要、OCR 引擎/版本、处理状态和失败/疑似乱码页。区分原始文字与 OCR 文字；有可靠置信度则保留，没有则不要伪造。
- 用中文、英文、旋转页、表格/多栏、数字与单位样例人工对照原图；记录漏字、数字替换和行列串联，不能只验“输出不为空”。不清楚的值标记待核对，不能补写成确定事实。
- 小样本导入测试副本后，引用能定位原文件与页；正常文字 PDF 不明显退化。对照问题能检查 OCR 恢复的证据是否真实进入回答，失败页不能显示为无警告的完整成功。
- 工具通过后，另提交导入集成；旧文档重处理及索引迁移需单独列范围、备份与历史引用兼容性。

引擎可评估 [PaddleOCR 官方快速开始](https://www.paddleocr.ai/main/en/quick_start.html)，但本交接没有锁定其版本，也没有安装或下载模型。

## 第三轮：MCP 小服务（方向已确认）

用户已确认：**将知识库作为 MCP 服务，供 DeepSeek 等客户端查询**。本轮不是让 RAG 调用外部 MCP 工具，不开发后者。

最小范围：文档列表、带 `document_ids` 的检索、按来源身份取原文；需要问答工具时复用已有生成路径，明确区分原始证据与生成回答。工具返回文件名/页码/版本等可核对来源，不把检索分数称为正确率。

- 本机客户端可先用 stdio，确需远程客户端再考虑 Streamable HTTP；使用与选定 SDK 版本对应的接口。[MCP 官方运行说明](https://py.sdk.modelcontextprotocol.io/run/)区分这两种传输，不为本机调用额外开放生产端口。
- 复用同一份范围约束、检索排序和来源引用；不复制索引或另写一套答案逻辑。不附加任意命令执行、文件删除或重建索引工具。
- 验收必须使用 MCP 客户端完成初始化、列工具、调用、无结果/错误处理及范围过滤，而非只有普通 HTTP 200。客户端与网页在同一问题/文档范围下得到可核对的一致来源。
- MCP 提供调用入口，不直接提升答案准确率。接入会把原文送至外部模型的客户端之前，说明资料流向并取得用户确认。

## 准确率验收：贯穿每一轮，不另起长期框架工程

复用已有评测记录，从真实使用中积累“问题、对应原文/页码、预期事实与条件、实际回答和引用”。目前没有用户确认的真实业务验收集；开发者整理的诊断样例不能包装成业务金标或总体正确率。

分别定位：解析/OCR 漏失 → 切分破坏关系 → 召回遗漏 → 排序/选段遗漏 → 生成改错或引用不支持。证据已完整进入模型却答错时，修生成环节，不继续盲目扩大召回；数字、单位、限定条件、版本和冲突均要核对。可回答的文档操作步骤应正常解释，不因泛化的“安全规则”一律拒答；但文档示例不能被说成现场当前实测值。

固定前后对照条件，留出未用于调试的新题，保留全部首次回答及失败。分别报告错误结论、回答有用性、误拒绝、证据与引用支持、耗时；不靠大量拒答、只挑最好一轮、两道特例或 mock 测试证明准确率提高。模型/提示/检索/切分/OCR 尽量分开改，便于归因。

## 每轮提交与审核反馈

DeepSeek 提交：Git 分支、提交或 PR，以及明确的基线与待审提交、目标与改动文件、可运行测试命令和结果、失败与未测项；前端附桌面/手机操作结果，检索/OCR 附脱敏的输入、来源和前后输出。私有文档、数据库、模型、密钥和原始业务回答不进入公开仓库，不只给“已完成”的文字说明。

Codex 返回：审核版本与范围、可复现问题（文件/行号、触发步骤、影响）、优先级及最小修改建议、复测结果和未覆盖范围。P1 阻塞合入；P2 普通缺陷也需处理或明确接受，建议项不混作缺陷。结论区分“通过 / 修改后复审 / 未充分验证”，不会仅凭 DeepSeek 的测试声明批准。

审核通过只说明该差异在已测范围内可接受；Git 提交/推送、合并、个人服务部署、索引重处理与生产发题分别记录，不自动合并或部署。

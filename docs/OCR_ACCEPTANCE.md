## 本轮修复

`scripts/ocr_preprocess.py`：

1. `OcrLine` 增加文字框几何（x/y 中心、宽高），`RapidOcrEngine.recognize` 从
   RapidOCR 的 `boxes` 读取；旧引擎/假引擎没有几何时保持 None，不影响原行为。
2. `_mostly_vertical`：文字框高明显大于宽（横排文字被转 90/270）时视为竖直；
   首轮结果为竖直或字符过少/分数低时，触发 90/270/180 旋转尝试。
3. 旋转候选优先选“文字框水平”的一轮，再比较置信度/字符数；选中旋转轮次后
   `_sort_reading_order` 按行中心 y/x 排序，修复 90/270 页的行序反转。
4. 普通页（首轮水平且可靠）不改变引擎顺序；无几何信息时不做任何排序，避免伪造行序。

## 未解决 / 边界

- **180° 页行序**：引擎方向分类对正/倒都能识别且分数接近，页面级方向无法从 OCR
  文本或框形状判定；需要人工方向标记或独立方向分类器（不在本轮小范围修复内）。
- 复杂表格/多栏仍不做版面重建；本验收只证明简单网格样例的行列顺序。
- 合成样例的字符召回 ≠ 业务回答正确率；本轮没有生产索引/服务改动，也没有重处理旧文档。
- 未跑真实私有扫描件；该验收只能证明工具在已知版式上的行为，不代表全库准确率。

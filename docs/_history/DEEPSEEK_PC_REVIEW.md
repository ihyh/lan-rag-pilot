## 交回结果格式

请在项目中创建**新的** `data/eval/reports/deepseek-review-<实际日期时间>/` 目录，不覆盖现有证据。至少输出：

- `REPORT.md`：执行环境、源码/安装身份、实际覆盖、各状态数量、严重问题和未完成项。
- `checklist.csv`：本文每个编号一行，列为 `id,status,environment,evidence,note`；所有未做项目都保留。
- `findings.md`：每个问题按下列模板，环境问题与产品缺陷分开；保留完整原答和失败，不拼接不同版本的通过记录。
- `evidence/`：必要截图、失败请求/响应、脱敏控制台日志和原文对照。截图须能证明URL、动作结果和对应问题；长答案保存文本，不只截首屏。

```text
问题ID：DS-001
关联检查项：E01
严重性：P0 / P1 / P2 / P3
类型：产品缺陷 / 环境阻碍 / 资料问题 / 待用户业务判定
环境：正式或隔离；URL；浏览器；视口；角色；源码/安装身份
前置条件：资料ID、版本、会话ID、范围等（不写凭据）
复现步骤：可由开发者独立执行的最少步骤
预期结果：对应哪条现有契约、用户要求或来源原文
实际结果：完整报错/行为；回答问题附完整原答
证据：本地文件相对路径、请求状态、时间、来源ID/位置/逐字原文
复现频率：例如1次执行1次失败；所有尝试均保存
影响：会影响谁、哪个流程；与既有通过证据的区别
定位建议：可选；推测须标明，未证实的函数不能写成根因
本轮改动：无应用改动；如有正常测试数据新增须逐项列出
```

P0用于越权泄露、数据破坏或服务不可用；P1用于核心问答/引用/范围/历史链路错误；P2用于重要功能或交互缺陷；P3用于轻微视觉/文档问题。等级应按实际影响说明，不能把工具无法控制浏览器等同于网站P0。

最后明确列出“已完成、失败、阻碍、跳过、未执行、待用户判断”，并列出本轮产生的测试数据和进程收尾情况。把报告、问题清单与相关证据交回用户，由原开发助手逐项复现、修改和回归。

## 3. 技术选择

### 3.1 保留现有前后端，先交付体验

第一版保留Jinja模板、原生JS和CSS，不迁移SPA，不增加前端构建链。现有主题变量、原生details与模板足够实现视觉目标；迁移同时会触碰会话、检索范围和流式状态，增加非必要回归。

Vue以后可按交互规模单独评估；它本身也基于HTML/CSS/JS并支持渐进采用，并非必须全站重写。[Vue官方说明](https://vuejs.org/guide/introduction.html)

### 3.2 复用检索和本地模型，不靠新增模型环节堆功能

保留现有混合检索作为对照，不默认扩大Top-K、开启CPU重排、接入模型挑源或自动云端回退。对真实失败逐层核对：原件→解析→候选→最终证据→实际回答分派→模型解释→引用。只在定位阶段后做最小修复。

表格有明确表头/单元格关系时优先验收现有确定性路径；不能覆盖的资料仍走原生成路径。不能把散文伪装成表格或加入CEID专属答案字典。通用中文/数字召回、补证/续段只作同条件独立对照，收益证实后才考虑启用。

### 3.3 来源先于展示，新增字段兼容旧记录

确定一个有限的来源元数据契约，不另造知识图谱或导入平台：

- 文档身份：原件SHA、真实文件名、版本、适用范围；
- 原文位置：PDF物理页；Word段落/表号行列；图片本图或区域；日志原文件行范围；网页URL/标题/采集时间/标题或段落位置；
- 提取状态：原生文字或OCR、可疑/失败/未提取图形，不伪造置信度；
- 答案引用：原始来源编号、有序实际输入片段全文和上述身份快照。

新增回答不再只保存300字摘要：复用现有`chat_sources.excerpt TEXT`保存有界的实际引用正文，补最小可空的来源元数据快照字段；网页原始来源元数据需要最小可空文档字段。具体字段在实现前以真实样例锁定，新增迁移须幂等且旧业务行守恒。

旧历史不足300字之外的部分不能事后猜回；若只能从当前索引打开相关文字，明确“当前索引内容”，不冒充当时模型输入。新格式字段是可选扩展，保留旧`answer/sources/status`与NDJSON协议兼容。来源原文按安全文本呈现，不执行网页或文档HTML。

## 4. 实施顺序与完成条件

### M0：冻结基线和人工验收准备

1. 记录开发全文件指纹、安装版差异、配置、模型和原件/索引身份。测试使用新隔离目录、数据库一致副本和未占用的非生产端口。
2. 以用户真实问题为先整理约10题：独立问题、设备/协议/版本、原文、适用范围、完整可答/部分可答/需追问/无依据、是否计算。未知项保留待人审，不能由AI自行批准。
3. 用户核对后才形成首批验收标准；已有消费题保留为回归，不冒充未见发布集。后续另补不参与调参的真实题，不能把首次10题包装成全库正确率。

完成条件：基线身份可回放；表格参数、编号查询、完整操作步骤等有明确逐事实判据；当前失败原样保留。

### M1：完整引用证据与定位

1. 新回答持久化实际有序来源正文和身份，不进行自由裁行；保留版本/真实位置与旧历史兼容。
2. 新增经过权限校验的引用原文展示路径；正文引用点击后展开并聚焦精确来源，不合并同页不同块的身份。PDF可跳页，其他格式先精确展示索引段落/表格坐标/日志行与原件入口，不能伪称Word原生光标定位。
3. 来源失效、历史短摘要、格式不支持定位时明确说明，不用当前片段偷偷覆盖历史证据。

完成条件：超过300字的关键限定能在保存后重新读取；重复/相邻引用和同页多块正确映射；恶意方括号/URL不会变成错误引用；历史、同步、流式结束后来源一致。格式合法不计事实通过。

### M2：网页、截图、日志入库

1. 网页先锁定指定4个文章URL，不跨栏目或自动扩站。保存取得的源快照、清理后的正文和URL/标题/采集时间。正文中的表格、链接和图片引用保持可追踪，抓取失败不造正文；嵌图未识别时显示不完整状态。
2. 网页转换遵循“原件保留、结构核验”的导入规范。[MarkItDown官方支持HTML转换](https://github.com/microsoft/markitdown)，但该工具尚未安装；只有现有依赖无法可靠提取实际页面时，才在隔离工具环境评估它及必要extras，不把全格式转换引擎塞入在线主环境。禁用自动插件与远程视觉，不处理音视频。
3. 截图先支持PNG/JPEG，复用独立CPU OCR引擎、队列、可疑内容审核和明确失败流程；保留原图SHA与原图入口，不拿临时转出的PDF冒充原件。代码已识别的其他图片后缀不等于全都承诺首版支持。
4. 日志支持TXT和明确的LOG文本入口；保留原文件、编码/原始行号，提取失败显式阻断；多行报文/错误堆栈优先按真实记录边界成块，保留重叠来源，不按同一数字跨设备混配。验收实际日志后再扩大格式，不新增视频或二进制日志解析。
5. 各格式接同一文档/版本/范围和引用链路，持久保存，去重保守，不重建整个旧库。

完成条件：逐份原件身份与正文/图片/日志行位置可对照；4篇范围核实且逐项报告导入成功/失败/部分提取；每类正反例含乱码/空内容/提取失败/重复/取消重试；旧资料和历史答案不变。

### M3：追问、冲突、步骤与计算的统一回答约束

1. 用实际分派同步/流式验收已有表格候选，再决定保留/修复；Index/Value/说明/默认/现场值严格分开，含0、负数、缺值、重复列等边界。
2. 定义可选的回答辅助状态（事实答复/需澄清/部分可答/资料不足/冲突），共享同步/流式/历史路径；标记不当作真值。不同设备或协议但同号时要求明确上下文，原始范围不被隐式扩大。
3. 模型产生澄清问题时保留原问，补充回答仅用于明确设备/协议/版本，历史助手答案不作事实来源；限制连续追问并允许用户新建/取消。无证据不得编“机台状态需要先开盒”等额外条件。
4. 有据的完整步骤按顺序、条件和参数呈现，不受默认短答字数截掉关键前提；仅标签/半句时明确证据边界，不补算法。
5. 计算先限制为来源明确的数量与单位换算，优先用标准库Decimal和白名单单位；输出原文输入、来源、算式、明确“计算结果”。不执行模型给出的Python/eval/工具代码，不猜单位或从跨设备参数拼算；单位缺失/冲突则说明不可计算。

完成条件：同号不同设备不猜；缺资料与部分可答不误称全库不存在；冲突逐项保留；每个计算有输入出处和标记；自然语言重述不引入新事实。主/独立AI逐事实复核+用户业务确认，不能仅靠系统提示或关键词打分。

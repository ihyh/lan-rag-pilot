# 文档版本与适用范围

资料管理每行的“更多 → 归档与适用范围”可设置设备标注、适用说明和“启用 / 历史”状态。当前界面保留已有版本标签，不提供单独编辑版本号的输入框。上传时间、同名文件和版本号都不会自动决定哪个来源权威。

删除与设为历史不同：删除资料会同时删除原件、片段以及旧回答中绑定该资料的引用快照，旧答案正文不会重写；删除不可用来保留可回溯来源。需要保留原件和旧引用时，应设为历史。删除确认框也会说明这一影响。

- **启用**：已就绪后可参与普通问答和默认原文检索。
- **历史**：原件、索引片段和旧引用仍保留，停止参与普通问答与原文检索。不会删除向量，也不需要为恢复启用重新索引。
- **替代资料**：将旧资料设为历史时，可选择另一份已就绪且启用的资料。可不指定替代项；不能指向自身、失败文档或另一份历史资料。
- **恢复启用**：必须清空旧资料的替代项。操作不会自动停用其他版本；需要管理员核对适用范围后决定。

版本与适用范围操作和审计在同一事务内保存。现有文档迁移后默认全部启用，不自动推测新旧关系。适用范围是供人核对、搜索与勾选的说明，不是模型推断的自动设备路由。

问答页面按文件名、版本或适用范围查找并勾选。已经打开的页面需要刷新资料列表；如果某个对话固定选择的文档后来设为历史，再追问会提示重新选择，绝不悄悄换成全库或替代版本。旧答案和引用仍可查看。

资料检查仍显示历史文档及其替代项。默认原文检索只查启用文档；勾选「包含历史版本」后可对照旧正文，结果逐条标注历史状态。此选项不改变问答范围。

普通问答和默认原文检索排除历史资料；原文检索可显式勾选包含历史版本。历史原件可在管理页显式核对，显示状态和替代项，但不能把历史文字当作当前适用结论。

数据库以兼容方式增加 `lifecycle`、`replacement_document_id`、`applicability` 三列。发布时需先备份，索引不重建。旧版代码可容忍这些附加列，但降级后不会执行历史文档过滤，因此回退属于恢复旧行为，不等于保留新版本规则。

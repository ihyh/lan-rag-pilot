# 证据补全：问题点名字面标识符（默认关闭）

真实问题错误定位（25 条真实问答 + 12 题人工核对包）显示两类不同的缺失：

1. 检索只选中一个文档的片段，另一份资料里同号/同名字段的原文没有进入上下文
   （如告警代码 2,1/3,23 只给了一个文件、P150 bit4 只给了 xlsx 一侧）；
2. 目标行/目标字段被向量检索排到后面，模型只能回答“片段未提供”
   （如 Input Monitor Time 的 Parameter 第 18 行）。

本模块只做**可逐字核对**的补证：不重切块、不重算向量、不改召回排序与引用编号语义。

## 开关与默认

| 环境变量 | 默认 | 行为 |
| --- | --- | --- |
| `RAG_EVIDENCE_COMPLETION` | `0` | 选段后按问题点名的字面标识符补入原文片段；默认关闭，需显式开启并做前后对照 |

默认关闭；开启只改变“送给模型的上下文”，不改变检索分数/排序、chunk、Top-K、权限范围或数据库。
与 `RAG_CONTEXT_CONTINUATION` 相互独立，可分别对照，也可组合使用。

## 行为

1. 从问题中提取可逐字定位的标识符（最多 6 个）：
   - 告警代码对（`2,1` / `3,23`，中文紧邻也能识别）；
   - 十六进制码（`0x A5` 等）、`SxFy`（`S2F20`）；
   - 字母+数字字段（`P150`、`bit4`、`Byte1`）；
   - 由 2–4 个英文单词组成的字段名（`Input Monitor Time`）；
   - 引号内的短句。
   停用词（PLM/PLUS/E84/ASCII/SECS 等泛词）不触发补证；普通问句没有标识符时不补。
2. 在**当前会话范围**内按字面搜索 ready 文档的 chunks（`lower(content) LIKE`），把包含该
   标识符的原文片段作为独立来源附加：保留真实 `document_id/chunk_id/page/seq`，
   `score` 留空、`relation=question_literal`、`matched_literal` 记录命中的字面。
3. 每个标识符优先覆盖不同文档（保留同号不同定义）；同一标识符最多 3 段，总数最多 4 段；
   已在结果中的 chunk 不重复附加。
4. xlsx 片段若不在文档首段，额外附该文档首段作表头来源（`relation=table_header`），
   避免只有目标行没有列语义。

## 真实问题前后对照（私有，不提交仓库）

同一模型/温度/范围，只打开 `RAG_EVIDENCE_COMPLETION`（续段开关关闭）：

| 题 | 必要来源覆盖（开→关） | 结果 |
| --- | --- | --- |
| H01 代码 2,1 两份定义 | 1/2 → **2/2** | 两个文件的定义都进入上下文 |
| H02 代码 3,23 两份定义 | 1/2 → **2/2** | 不再出现“另一份未找到” |
| H03 P150 bit4 跨文档 | 1/3 → **2/3** | 另一文档片段进入，但补入了同表其他 bit4 行噪声 |
| H04 Input Monitor Time | 0/2 → **2/2** | 目标行 + 表头进入上下文 |
| H12 P20 现场值 | 0/2 → **1/2** | 补到表头；目标行仍未被字面命中 |
| 25 条真实使用 | 1 条覆盖改善、0 条回退 | U16 补到 1/3 必要来源 |

**重要限制（未解决）**：证据补齐后生成仍会读错。例如 H04 目标行已包含
`A18=20；B18=Input Monitor Time`，回答仍写成“索引为 18”（把行号当索引值，实际索引是 20）。
这说明“完整证据上下文”只解决“证据在不在”，下一步必须改生成方式（直接回答＋逐项依据＋
数字/引用程序检查），并以同一批题前后对照；不能把本次覆盖提升当成准确率提升。

## 边界

- 只做字面匹配，不做语义扩展、不问模型“还需要什么证据”；
- 字面在范围内不存在时（如 P20）不补、不猜；
- 不跨出会话范围，不改变权限/可见性判断；
- 开关关闭时行为与改造前完全一致。

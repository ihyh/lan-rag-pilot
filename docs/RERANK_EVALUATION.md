# Rerank 评估：选段丢失、同条件对照与延迟预算

日期：2026-10-21
范围：只评估检索/选段与本地 CPU 重排；**不启用/不部署重排，不改生产索引/数据库/服务**。
私有题目、原文和逐题报告只保存在忽略目录；本文件只写方法与聚合结果。

## 问题：召回了，但选段时丢失必要证据

在真实语料快照（34 文档 / 1279 chunks）上，用 12 条人工固定证据题做离线证据集评估
（`scripts/retrieval_eval.py`，同一 DB、同一 Top-K=3、同向量模型）：

| 指标（无重排） | 结果 |
| --- | --- |
| 候选召回率 candidate_recall | 79.2% |
| 最终证据召回 evidence_recall | 45.1% |
| 证据完整题数 | 3/12 |
| 候选已召回但最终缺证的题 | **6/12**（selection_lost_evidence） |
| 候选本身未召回的题 | 3/12（H02/H03/H05 类） |
| 检索 p50 / p95 | 22.7 ms / 135.1 ms |

逐题核对：部分必要证据在候选中排名 5、8、18 位，Top-K=3 选段无法全部保留；
这不是“向量没召回”，而是候选预算/排序问题。另有 3 题候选池本身缺失，重排无法修复。

## 同条件开关对照（只变 rerank，其他不变）

本地 `BAAI/bge-reranker-v2-m3`（官方 revision，CPU，窗口 512，batch 4），同一 DB/题目/Top-K：

| 指标 | 重排 OFF | 重排 ON |
| --- | --- | --- |
| 候选召回率 | 79.2% | 79.2% |
| 证据召回率 | 45.1% | **62.6%** |
| 证据完整题数 | 3/12 | **5/12** |
| 选段丢失题 | 6/12 | 4/12 |
| 重排新增完整题 | — | 2 题（另有 1 题部分改善） |
| 仍未完整题 | 9/12 | 7/12 |
| 检索总耗时 p50 / p95 | 22.7 ms / 135.1 ms | **39.2 s / 44.1 s** |
| 重排分段 p50 / p95 | — | **39.2 s / 44.1 s** |

重排后仍失败的题中，3 题是候选未召回（重排无法解决）；其余是 Top-K/排序仍不足。
**重排确实提高了证据完整度，但 CPU 延迟不可接受。**

### 更便宜的确定性路径（对照，不是重排替代品）

用现有、默认关闭的字面补证 + 续段（`RAG_EVIDENCE_COMPLETION` / `RAG_CONTEXT_CONTINUATION`）
作用在**同一批 baseline 选段结果**上：

| 指标 | 无开关 | 字面补证 | 字面补证+续段 |
| --- | --- | --- | --- |
| 证据完整题数 | 3/12 | 5/12 | **6/12** |
| 证据召回率 | 45.1% | 61.8% | **66.0%** |
| 选段丢失题 | 6/12 | 4/12 | 4/12 |
| 额外耗时/题 | — | 5.8 ms | +0.35 ms |

对字面标识符/字段名类题（如按代码、字段名补原文）这是毫秒级恢复；
但它只覆盖“问题点名了字面标识符”的类别：**原候选池**仍显示 H02/H03/H05 候选缺失，
其中 H02 在补证+续段后已由补入来源补齐为完整证据（不能再用原候选标记否定最终完整性）；
H03/H05 的候选缺失、H07/H08 的步骤类证据、H12 的“字段说明 vs 现场值”仍需其他路径。

## 延迟预算与结论

**建议的可接受预算（个人本地交互式问答）：**

- 检索+选段总耗时 p95 ≤ **2500 ms**；
- 若启用重排，重排增量 p95 ≤ **1500 ms**、p50 ≤ **800 ms**；
- 超过预算就不得默认启用；不能用“质量更好”掩盖交互不可用。

实测 CPU 重排 p50 39.2 s / p95 44.1 s，超预算约 **15–30 倍**。
同机再测 20 个候选、单窗口：约 **18 s**；60 个候选约 **28–29 s**（batch 4/16 无显著差异）。
本机（Ryzen 5 5500X3D，6 核，CPU 推理）**已测配置均未满足上述预算**；
这不等于证明所有可能的 CPU 优化都不行，但足以暂缓当前 CPU 方案。

**结论：CPU 重排暂不启用。** 保持 `RAG_RERANK_ENABLED=0`；不据此推进 rerank 上线。
若确需重排，可选路径（均需另行验证/授权）：
1. GPU 推理（本机有 RTX 5060 Ti，但当前部署 venv 是 CPU-only torch，需单独环境与部署决策）；
2. 量化/更小模型（必须重跑同一证据集，证明质量不退化）；
3. 非交互式异步预处理（不能当作在线问答延迟）。

当前更划算的方向是先评审/启用毫秒级的字面补证与续段，并对表格/参数类事实用确定性拼接；
重排留到有 GPU/可行延迟方案后再做同条件对照。

# M3.1：回答完成状态护栏（工程候选完成，未部署）

本阶段只处理传输与生成的明确失败，不判断一句话是否有原文支持，也不按标点猜“步骤完整”。正常结束状态同样可能漏条件或产生无依据扩写，仍需逐事实验收。

## 最小契约

| 模型服务响应 | 应用处理 |
| --- | --- |
| 明确`finish_reason=length` | 返回`llm_incomplete`，不把已截断正文记作成功 |
| 明确`stop` | 继续已有正文/引用格式检查；不表示事实或完整步骤已核实 |
| 其它明确结束原因或错误类型 | 返回`llm_bad_response`，不当作正常最终答复 |
| 缺失或NULL结束原因 | 兼容旧端点，仍检查正文/引用格式；没有完整性证明 |
| 空白或规范化后为空 | 返回`llm_bad_response`，不保存空的成功答复 |

同步和流式使用共用检查。流式已采用完整缓冲后输出正文：明确失败时不先发送半截`delta`，也不发送成功`sources/done`。Web保留错误记录，不为失败答复保存成功引用；MCP返回工具错误且不写个人问答历史。不开新模型调用、不自动重试、扩token、重建索引或切云端。

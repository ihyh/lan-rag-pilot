# 表格参数题：确定性回答（实验，默认关闭）

## 为什么

真实问题诊断中，证据已经进入上下文但模型仍读错：

- H04：目标行 `A18=20；B18=Input Monitor Time；C18=/；D18=...；E18=...单位ms`
  在片段里，回答却写成“索引为 18”（把行号当索引值），并把 Unit/Mark 列的单位说反；
- H12：把表格第 20 行的 `MappingEncoder` 当成问题里的 P20，或把字段定义当现场当前值。

这类题的关系**完全由原文结构确定**（工作表、行号、列字母、表头名称、单元格值），
不需要模型自由生成。本模块只对这类题做服务端拼装回答，其余问题仍走原生成路径。

## 开关与默认

| 环境变量 | 默认 | 行为 |
| --- | --- | --- |
| `RAG_TABLE_ANSWERS` | `0` | 表格参数题命中时由服务端按单元格/表头直接回答；默认关闭，需显式开启并做前后对照 |

开启只改变“表格参数题”这一类的生成方式；不改检索、chunk、向量、Top-K、权限或引用编号语义。
与 `RAG_CONTEXT_CONTINUATION` / `RAG_EVIDENCE_COMPLETION` 独立，可分别对照。

## 命中条件（全部来自原文结构）

1. 检索来源中存在 `.xlsx` 片段，且能解析出
   `工作表《Sheet》第 N 行：A18=20；B18=...；` 行与 `第 1 行` 表头；
2. 问题点名了字段（Name 列表头匹配，如 `Input Monitor Time`）或 `P<数字>`
   （按 Index 列值定位，如 P20 → A 列 =20 的行）；
3. 问题问到以下属性之一：索引、字段说明/含义、单位（Unit/Mark）、现场当前值/实测值。

命中后输出：

- 工作表、真实行号、字段名、目标行来源编号 `[n]`；
- 问索引 → 取 Index 列值，并明确“行号 N 不是索引值”；
- 问字段说明 → 取 Description 列；
- 问单位 → 分别给出 Unit 列与 Mark 列的真实单元格文字；
- 问现场当前值 → 说明只有字段定义、没有该设备的实测/读取值记录，**无法确认现场实际设置值**；
- 同名字段出现在多份资料时逐份列出，不裁定哪份优先。

不命中（非 xlsx、无属性词、字段找不到、表头解析不可靠）时返回 `None`，交回原模型生成路径；
不做猜测、不调用模型、不伪造值。

## 边界

- 只支持“字段行 + 表头”结构可解析的 xlsx；合并单元格、复杂多行表头可能不命中而回退；
- 不做语义推断（“适用于/原因是/应该”都不生成）；
- 不改变检索结果与引用编号；输出引用编号来自检索来源顺序；
- 关闭开关时行为与改造前完全一致。

## 验证

- `tests/table_answers_check.py` —— **21 项通过**：
  行号≠索引、字段说明、Unit/Mark 区分、P20 按 Index 定位、现场值未知、多来源同名字段、
  非 xlsx/无属性/字段未命中回退、`llm.chat` 开关开启时不调用模型。
- 真实固定证据 A/B（私有，不提交仓库）：H04 由“索引 18/单位说反”变为按
  `A18=20、C18=/、E18=单位ms` 的确定性回答；H12 说明“P20 对应字段定义 + 无法确认现场值”。
  其余题不触发、继续走原生成；该结果只证明这类表格题的关系拼装，不代表总体准确率。
- `tests/run_checks.py` 全量回归通过；开关默认 `0`，未开启、未部署。

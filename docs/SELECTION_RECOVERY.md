# 选段丢失恢复：确定性补证/续段同条件评估

日期：2026-10-21
范围：检索选段阶段；不启用 CPU rerank、不改生产库/服务、不部署。
背景：[rerank 评估](RERANK_EVALUATION.md) 已证明 CPU 重排在建议预算内不可行；本轮处理
“候选已召回但 Top-K 选段丢失必要证据”的价廉替代路径。

## 同条件结果（12 条人工证据题，同一语料快照/Top-K=3）

评测器新增 `--evidence-completion` / `--context-continuation`，**直接复用生产开关的
`attach_literal_evidence()` / `attach_continuations()`**，其余条件完全一致：

| 指标 | 无开关 | 字面补证 | 字面补证+续段 |
| --- | --- | --- | --- |
| 证据完整题数 | 3/12 | 5/12 | **6/12** |
| 证据召回率 | 45.1% | 61.8% | **66.0%** |
| 初始候选召回（补证前） | 79.2% | 79.2% | 79.2% |
| 来源总数/12 题 | 36 | 59 | 70 |
| p50 / p95 检索耗时 | 18.4 / 26.6 ms | 22.3 / 36.5 ms | 22.8 / 45.2 ms |

逐题变化：字面补证修复 H01（跨文件同码定义）与 H04（Input Monitor Time 行/表头）；
续段额外补齐 H02（同码另一份资料）；H03/H05/H11/H12 仍不足；H06/H09 等原本完整题
不因开关丢失证据，但会因跨文档定义新增来源（H10 3→9 条）。
**初始候选召回未变，不代表没有二次召回**：字面补证 helper 会在许可范围内做 SQL 字面
扫描并能补入初始候选池之外的 chunk；报告应区分“初始候选召回”与“补证后的最终证据覆盖”，
不能据初始列表不变否认二次召回。

## 回答级小样本对照（3 题，真实本地 qwen3:4b-instruct）

用同一批选段来源走生产 `llm.chat`；已按严格判据复核，**关键字/引用命中不等于整答通过**：

| 题 | 无开关 | 字面补证/续段 | 整答支持 |
| --- | --- | --- | --- |
| H01 两份资料的同码 2,1 | 错称 PlusPro 无此代码 | 两份原文含义正确；另加“六轴/硬件通道配置异常”等来源未支持解释 | 部分事实正确，整答未通过 |
| H02 两份资料的 3,23 | 误拒答“未提及 3,23” | 两份故障文案正确；另加“与机械轴/安全状态无关”等来源未支持排除 | 部分事实正确，整答未通过 |
| H04 Input Monitor Time 索引/单位 | 误拒答 | 单位 ms 正确，但仍把行号 18 说成索引 18（正确索引应 20） | 未通过（wrong_fact） |

因此：**补证能修复“缺证据导致的错误结论/误拒答”，但不能修复无依据扩写或把行号当索引的
生成错误**。H04 类别需结构化表格回答或生成侧修复；H01/H02 的扩写也需生成侧收紧。

## 决策

- 本轮**不把两个开关设为默认开启**：证据完整度有改善但来源数增加（36→70），
  回答级 H01/H02 仍有来源未支持的扩写、H04 仍有生成错误；需生成侧收紧与复审后再决定。
- CPU rerank 继续关闭。
- 不把初始候选召回不变或证据召回提升写成整答正确率提升。

## 评测边界（复核 E1 修复）

评测器现在与生产 `retrieve_sources` 一样，在**无候选**或**空文档范围**时短路，不调用
补证/续段 helper：

- `scope is not None and len(scope)==0` 表示“没有可见文档”，不得退化成全库；
- `hits` 为空时产品路径返回 `no_hits`，评测器也不得补出答案；
- 正常有 hits 且范围非空时才按顺序调用两个生产 helper。

回归：`tests/retrieval_eval_boundary_check.py` **9/9**（纯边界 + 完整分支调用/不调用）。
本批保存的 12 题均有候选且无空 scope，因此原 `3→5→6` 指标不变；该边界不改变既有有限结果。

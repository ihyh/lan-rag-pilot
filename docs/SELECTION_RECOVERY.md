# 选段丢失恢复：确定性补证/续段同条件评估

日期：2026-10-21
范围：检索选段阶段；不启用 CPU rerank、不改生产库/服务、不部署。
背景：[rerank 评估](RERANK_EVALUATION.md) 已证明 CPU 重排在建议预算内不可行；本轮处理
“候选已召回但 Top-K 选段丢失必要证据”的价廉替代路径。

## 同条件结果（12 条人工证据题，同一语料快照/Top-K=3）

评测器新增 `--evidence-completion` / `--context-continuation`，**直接复用生产开关的
`attach_literal_evidence()` / `attach_continuations()`**，其余条件完全一致：

| 指标 | 无开关 | 字面补证 | 字面补证+续段 |
| --- | --- | --- | --- |
| 证据完整题数 | 3/12 | 5/12 | **6/12** |
| 证据召回率 | 45.1% | 61.8% | **66.0%** |
| 候选召回骨架 | 79.2% | 79.2% | 79.2% |
| 来源总数/12 题 | 36 | 59 | 70 |
| p50 / p95 检索耗时 | 18.4 / 26.6 ms | 22.3 / 36.5 ms | 22.8 / 45.2 ms |

逐题变化：字面补证修复 H01（跨文件同码定义）与 H04（Input Monitor Time 行/表头）；
续段额外补齐 H02（同码另一份资料）；H03/H05/H11/H12 仍不足；H06/H09 等原本完整题
不因开关丢失证据，但会因跨文档定义新增来源（H10 3→9 条）。
**候选召回骨架不变**说明改善来自选段补证，不是重新召回。

## 回答级小样本对照（3 题，真实本地 qwen3:4b-instruct）

用同一批选段来源走生产 `llm.chat`：

| 题 | 无开关 | 字面补证/续段 |
| --- | --- | --- |
| H01 两份资料的同码 2,1 | 错称 PlusPro 无此代码 | 两个文件分别给出正确含义 |
| H02 两份资料的 3,23 | 误拒答“未提及 3,23” | 两份资料分别给出正确故障 |
| H04 Input Monitor Time 索引/单位 | 误拒答 | 给出单位 ms，但**仍把行号 18 说成索引 18**（正确索引应 20） |

因此：**补证能修复“缺证据导致的错误结论/误拒答”，但不能修复模型把行号当索引的生成错误**。
H04 类别仍需结构化表格回答（`RAG_TABLE_ANSWERS`）或生成侧修复，属于后续阶段。

## 决策

- 本轮**不把两个开关设为默认开启**：证据完整度和 H01/H02 回答有改善，但来源数增加
  （36→70），且 H04 仍暴露生成侧错误；需要生成侧小样本对照/复审后再决定默认值。
- CPU rerank 继续关闭。
- 不把候选召回骨架不变、证据召回提升写成整体回答正确率提升。

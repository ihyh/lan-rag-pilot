# 检索质量验证

[返回首页](../README.md) · [模型重建](MODELS.md)

这里的文档范围是检索范围，不是部门/人员授权；当前共享文档权限边界见 [安全要求](SECURITY.md)。所有诊断在受控离线环境进行，不把资料或报告传到外部服务。

## 精确术语与语义混合检索

当前问题包含 `P20`、`ArmElev`、`RESET_AXIS` 等 ASCII 标识符时，先按完整标识符召回，使用 SQLite FTS5/BM25 排名，再与语义候选做倒数排名融合。大小写忽略，但 `P20` 不等于 `P200`，`RESET_AXIS` 不等于 `RESET_ALL`。问题中的标识符必须全部出现；没有精确匹配时保留原语义结果。

两路召回均遵守对话文档范围和 ready 状态。关键词来自当前问题；历史仍用于语义查询。纯中文问题保持原语义检索，本轮未实现中文分词、同义词扩展或跨页上下文拼接。

关键词索引随现有向量索引在内存中重建，无新增依赖或持久数据库表。语义分支保留最低相似度门槛；精确匹配可召回低于该门槛的片段，因此返回的 score 仍是原始余弦值，不能把它当作融合排名或答案置信度。最终来源仍去重且不超过 Top-K。

## 在数据所在主机验证

先在隔离诊断进程显式设置 RAG_DATA_DIR、RAG_DB_PATH、RAG_UPLOAD_DIR 和本地 RAG_EMBED_MODEL，设置 HF_HUB_OFFLINE=1、TRANSFORMERS_OFFLINE=1；脚本不会自动读取 .env。使用只读数据副本及完整本地模型，Python 来自该部署的离线依赖环境。容器卷不会自动映射到宿主机默认 data 路径。以下命令在含 app/ 和 scripts/ 的源码根目录执行，先核对实际目标路径，不能误读另一个空库。

`scripts/retrieval_diagnostics.py` 默认只输出反馈数量、待核对 chat ID 和耗时。加 `--chunk-preview --document-id ID` 会在内存中重新解析指定文档，比较新旧切片数量、短片段比例及原文非空白字符覆盖；不写数据库，不调用生成模型，不显示正文。

```bash
python scripts/retrieval_diagnostics.py
python scripts/retrieval_diagnostics.py --chunk-preview --document-id 6
python scripts/retrieval_compare.py
```

切片预览需要已有本地嵌入 tokenizer；不会联网下载。对比脚本使用现有 BGE，逐题独立回放至多 50 条负反馈问题，保留已存文档范围，输出向量/混合检索的来源 ID、精确术语覆盖数及检索耗时。它不发送生成请求，不创建问答记录；同一文档范围内的排名变化不代表正确率提高。

这些命令应在受控环境执行，报告及实际评测题不得提交。先在只读数据卷和隔离进程中运行，避免启动第二个生产写入服务。

## 人工核对与重建顺序

1. 用负反馈 chat ID 在已有管理界面核对问题；标出正确文档和页码、关键答案、是否应该拒答，填入 `data/eval/questions.jsonl`。不要把旧模型回答当作标准答案。
2. 在同一问题、同一文档范围、相同模型设置下比较检索命中、引用位置、答案忠实度和耗时。单独记录带精确术语与纯中文问题。
3. 单文档切片预览必须保持原文字符完整覆盖和引用页码。片段减少仅证明重复减少，不证明答案质量提高。
4. 确认候选切片能命中人工指定的答案位置，并具备受控回退资料后，再实际重建这一份文档。已有重建操作会替换 chunk ID，应在业务低峰执行并核对历史来源显示。
5. 单文档效果通过再扩大范围；未核验前保持现有活动切片。

## 自动回归

```bash

```

检索回归入口包括精确标识符、超出向量候选池的召回、文档范围、删除/重建、并发重载、原相似度语义及切块边界测试。完整 smoke 继续覆盖上传、查询、对话持久化和权限。合成用例通过不替代真实业务验收。

## 切换嵌入设备（CPU ↔ GPU）后建议重新索引

`RAG_EMBED_DEVICE` 改变的是**计算设备**，不是模型本身：维度不变，所以上传与查询两侧
都不会报错，现有的"维度不一致"检查也**抓不到**这种差异。

但浮点实现在 CPU 与 GPU 上不保证逐位一致，同一段文本两侧编码出的向量可能有极小差异。
对本项目的检索方式（归一化向量的余弦相似度）而言，这种差异通常远小于文档之间的语义差距，
一般不影响 Top-K；但**不能保证**在边界样本上结果完全不变。

因此：

- 切换设备后，建议在真实评测集或固定问题上复核一遍命中率，不要只看"接口返回 200"。
- 若观察到命中变化，对关键文档执行"重新处理"（重建切片与向量）即可让两侧一致。
- 与更换嵌入模型/切片参数不同，这是**轻量**操作，但仍应先备份。

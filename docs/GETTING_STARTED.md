# 第一次使用

[返回首页](../README.md)

本页适用于已经拿到网址和账号的人。尚未安装的个人用户先看 [Windows](WINDOWS.md)，团队管理员先看 [Ubuntu](UBUNTU.md)。

## 1. 登录与账号

打开管理员提供的内网 HTTPS 地址。个人同机测试可用 `http://127.0.0.1:8088`。证书告警应由 IT 修复或安装受信任的内部 CA，不要忽略告警。

输入个人账号和密码，不要多人共用 root。全新数据库的 root 初始密码由安装管理员通过 `RAG_ROOT_PASSWORD` 设置，不存在通用默认密码。已有数据库不会因修改此变量而重置密码。

登录后使用右上角“修改密码”，填写并确认。按页面提示重新登录；忘记密码联系 root 管理员重置，不要删除数据库。按钮无反应见 [故障排查](TROUBLESHOOTING.md)。

| 角色 | 当前能做的事 |
|---|---|
| user | 查询共享文档、查看引用、管理自己的对话、提交反馈 |
| kb_admin | 上述操作，加共享文档上传、删除、重新处理 |
| root | 上述全部，加用户/角色/密码管理、全体对话、运行参数和审计 |

**对话权限与文档权限不同：** 对话通常只对本人和 root 可见，但共享文档不按部门或人员隔离。不能上传其中某个账号无权阅读的资料。

## 2. 用无敏感资料练习

管理员新建 UTF-8 文件 `入门演示.txt`，内容如下。这是虚构示例，不是真实设备规程：

```text
演示设备：DEMO-01。
每日巡检时间为上午 09:00。
巡检记录由值班员填写，保存在本地巡检台账中。
```

root 或 kb_admin 进入“管理”的文档页面上传，按界面填写设备等信息。等待状态成为“可用/ready”；上传成功但仍在处理，不代表能检索。失败先看原因，不要反复上传重复文件。

默认单文件最大 25 MB。支持有可提取文字的 PDF、DOCX、XLSX、TXT、MD；旧版 DOC 依赖 antiword。扫描 PDF 先在受控离线工具中 OCR 并人工检查；改后缀不会转换格式。

成功标准：文档状态可用，可以查看或下载原文件。

## 3. 提问与核对来源

新建对话，选择 DEMO-01 或仅选该文档。输入“DEMO-01 每日几点巡检？”。

文字会逐步出现；流式开始不代表完成。等整轮结束，展开回答下方“查看引用来源”，核对文件名、页码/段落/工作表等实际位置及引用片段。普通用户只能查看片段，文档管理员和 root 可打开完整原文。TXT 不一定有 PDF 式页码。

成功标准：答案提到 09:00，引用指向演示文档，原文支持结论。再问“DEMO-01 的采购价格是多少？”：原文没有价格，应拒答或说明资料不足；编造价格属于质量失败。

- 来源折叠时先点击小三角。
- 来源为空或位置错误，不能把回答当作有证据的结论；反馈给管理员。
- 引用表示系统提供了这些片段，不保证每个结论正确。
- 切换设备或资料范围时新建对话，避免前文干扰；范围选择不是访问控制。

## 4. 日常操作

用“有帮助/没帮助”反馈，补充问题、型号、预期原文位置。退出后关闭浏览器，不要在共享电脑保存密码。

删除对话不会删除原文。删除或重新处理文档会改变片段，可能影响历史引用；管理员操作前应备份和核对。

重要决策应由有权限的人员查阅原始资料确认，不能只依赖模型答案。

## 保存契约

日志扩展（2026-10-24开发候选）：按真实chunk冻结`source_kind=log`、`log`编码/SHA/行数与`line_start/line_end`闭区间；不信任检索返回的伪行号，历史不从当前索引补造。有效日志来源不使用page/paragraph；NULL/坏日志元数据降为`snapshot_unavailable`，旧已冻结历史保持原样。详见[LOG_IMPORT.md](LOG_IMPORT.md)。

- 新回答的 `chat_sources.excerpt` 保存最终 `sources.content` 全文，原样保留空白与换行，不再压成300字摘要。顺序仍对应答案中的 `[n]`。
- 新增可空 `source_snapshot` 列，JSON `format=1`，记录当时的 `filename`、`document_sha256`、`version`、`effective_date`、`applicability`。查询在一个短数据库读快照内完成检索与身份冻结，生成前释放；不会等模型时持有数据库事务。
- 同步 `sources`、流式 `sources` 事件及历史使用同一来源契约。流式来源事件在成功提交之后、原有 `done` 之前发送，现有客户端仍可在 `done` 后拉取历史。
- 原来的 `answer/sources/status`、来源 ID/页码/段落/分数保留；新增 `source_snapshot`（对象或null）及 `evidence_status`。

| evidence_status | 含义 |
| --- | --- |
| full | 新记录的完整检索片段与格式有效的文档身份快照已保存 |
| legacy_excerpt | 旧行没有快照，原摘录可能截断，不从当前索引补全文 |
| snapshot_unavailable | 快照损坏、字段不完整或格式未知；保留正文但不宣称完整历史身份 |

`full` 不表示完整页、完整文档、最终模型请求或事实支持已验证；来源正文在生成层还可能经过表头注释等处理。快照格式校验也不是密码学防篡改证明。

## 界面行为

- 有效引用编号可点击，展开并聚焦对应来源卡；同一页的不同编号不合并。
- 来源与答案都使用安全文本节点；代码、SECS类型长度、链接和未知编号不作为可点击引用。
- 展示回答时保存的文件名、版本和适用范围；PDF入口使用已有物理页参数，不承诺浏览器高亮，也不承诺Word原生编辑器段落定位。
- 原件入口指向当前文件，可能不同于回答时版本；核对历史时先看保存的片段与身份。

## 保持的边界

- 历史继续按当前权限过滤，撤权资料不能通过旧快照返回。
- 新来源迁移幂等；旧记录不回填，不更改原答案。旧score可空迁移保留快照及序列。
- 提交前停止不保存成功证据；成功提交后即使网络断开、客户端没收到done，历史可能已有记录，不能宣称已撤销。
- 仍沿用文档删除时级联删除 `chat_sources` 的旧行为；本轮不提供删除后证据永久保留承诺。
- 先前模拟测试及本轮合成库真实浏览器结果均不等于真实业务准确率或移动硬件验收。联合版本其他工作线与上线验收仍未完成。

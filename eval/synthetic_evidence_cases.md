# 图文与证据边界的人工回归样本

`synthetic_evidence_cases.jsonl` 是自包含的虚构样本，设备、接口、文件名和说明均为测试数据，不代表用户的实际设备。每行包含问题、模拟来源和人工判定标准。它不是生产知识库内容，不要导入生产库，也不要把其中结论套用到设备。

## 如何运行

1. 在隔离环境准备每个样本各自的来源，严格只提供该题的 `sources`；不同题含互相矛盾的虚构资料，不要混到同一测试库。允许使用相同来源名但各题必须隔离。图文题的 `image_caption` 是模拟说明；要测试网页显示须另建一张真实的测试图片，并用说明入库。
2. 为每题单独发问，记录实际检索范围、检索片段、引用、完整回答与页面显示。每题应观察“来源是否找对”和“回答是否得到来源支持”，这是两个不同结论。
3. 人工按 `expected` 判断答案是否保留条件、明确冲突、避免借用其他型号；同一题可多次运行并记录全部结果。未知题可以召回来源，同时应回答无法确认；不能把“有来源”当成“应当能回答”。图文题还需分别检查图片、手册是否可发现，以及候选和引用是否标示清楚；另测权限撤销、版本变化及真实浏览器。
4. `development` 用于调试，`holdout` 不用于设计或调整规则，完成修改后再运行；若查看或用于调参，就不再把该题当独立保留题。合成样本通过只代表这些样本，并不代表实际设备准确率。生产资料另选未参与调整的真实问题、由设备人员核对标准答案及来源。

本文件的格式是人工夹具，不兼容 `scripts/eval_runner.py`：该脚本以零来源近似判断拒答，无法准确评估“召回到资料但资料不足”的样本。不要用关键词或引用编号存在代替人工事实核对，不要把模型复核视为事实保证。
